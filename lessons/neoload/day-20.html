Week 7, Day 20: SLA Interpretation and Baseline Comparison

IntermediateAssess whether the system meets the agreed target under the same measurement conditions.

Session outcome

An SLA is not just a number. It is a business agreement tied to a transaction, a percentile, a time window, a workload, and a pass condition. This day explains how to evaluate a result against the target and how to compare a result against a baseline without hiding meaningful differences.

1. What an SLA needs

A valid SLA includes more than “the app should be fast.” It must describe:

  • Transaction: which action or business step is being measured.
  • Percentile: p90, p95, or another agreed threshold.
  • Time window: the period in which the performance is evaluated.
  • Workload: the user count or concurrency assumed in the run.
  • Pass condition: the specific threshold or requirement to satisfy.

If one of these factors is missing, the SLA is incomplete and cannot be evaluated with confidence.

2. Baseline comparison

A baseline is a control run used to compare behavior over time. It is only meaningful when the test setup is comparable: same script, same data profile, same environment type, same user mix, and same measurement method.

When comparing two runs, ask:

  • Were the same transactions measured?
  • Did the load pattern match?
  • Did the environment or deployment differ?
  • Were the data sizes or user mixes the same?
  • Did the result use the same time window and percentile calculations?

If these do not match, the comparison may be misleading or “inconclusive.”

3. Interpreting pass/fail

Results should be classified as:

  • Pass: the target metric meets the SLA threshold under the approved load.
  • Fail: the target metric exceeds the SLA threshold or the error rate exceeds the allowed boundary.
  • Inconclusive: the run did not match the control conditions or is missing evidence.

For example, a p95 login time may be within target at 100 users but fail at 300 users. The conclusion depends on the workload and the approved target. The report must say which workload level was used to evaluate the SLA.
