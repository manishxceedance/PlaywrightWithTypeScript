Week 3, Day 8: Extractors and Correlation

IntermediateCapture values that are created during runtime and reuse them correctly.

Session outcome

By the end of this day, you should understand what correlation is, why recorded values become invalid in later iterations, which values typically need extraction, and how to replace literal values with runtime-generated variables in NeoLoad.

Correlation is one of the most important concepts in performance scripting. Without it, a script may replay successfully once and then fail for the next user or the next iteration because the server expects a new value that the original recording never captured.

1. What is correlation?

Correlation means taking a value generated by the application during one request and using it in a later request. The application often creates this value when it authenticates, loads a page, updates a record, or generates a token. A later request then expects the current value and rejects an old or different one.

In a performance test, a recorded value is usually valid only for the exact session it was captured in. When another virtual user or another iteration starts, the server expects a fresh value. If the script keeps sending the old value, the request can fail with authentication errors, invalid session errors, validation errors, or record-not-found errors.

2. Why the recorded value fails later

Suppose the script records a login flow and the server sends a CSRF token. That token is valid only in the user session it was issued for. If a second virtual user reuses the same token string from the first user, the server may reject the request because it no longer matches the current session state.

Similarly, imagine a page loads a list of employees and the script selects the first employee ID. The application may later expect the exact employee ID from the current search response. If the script hard-codes a value from the first run, the request may fail or update the wrong record.

Correlation is not optional. It is the bridge between a single recording and a repeatable, realistic load test.

3. Extractors in NeoLoad

Extractors are the mechanism that captures runtime values from a response. A value can be extracted from HTML, JSON, XML, headers, cookies, or response bodies, depending on the application. The key is to capture only the value you need and save it in a variable.

Common extractor types

  • RegEx extractor: captures a substring matching a pattern in an HTML or text response.
  • JSON path extractor: reads a field from a JSON response body.
  • XPath extractor: captures a value from XML or HTML structure.
  • Header extractor: captures a value from a response header or cookie.
  • Variable or parameter extraction: stores a value after a page or request completes for later use.

The useful rule is to extract the smallest valid value that uniquely identifies the state you need. Do not extract large response bodies when only one field matters. Avoid storing sensitive or unnecessary information in variables unless the security and retention rules allow it.

4. The typical correlation pattern

  1. Open the response body or headers for the request that creates the value.
  2. Identify the exact value you need, such as a token, session ID, or record identifier.
  3. Use the correct extractor and name the variable clearly.
  4. Insert the variable into the later request where the recorded value previously appeared.
  5. Replay the script and confirm the later request accepts the extracted value.

Do not replace a recorded literal blindly. Always confirm that the value appears in the response you intended, that it is not an unrelated duplicate on the page, and that it belongs to the correct user session.

5. Practical HRMS example

Take the HRMS employee maintenance flow from Day 4. After signing in, the application may return a session cookie or a state value. That value is used when the script later loads the Employees list, submits a search, or saves an edit.

  1. Record the login request.
  2. Inspect the response for the authenticated session state or token.
  3. Extract the value into a variable such as sessionId or csrfToken.
  4. Apply the extracted value in the subsequent request that requires the active session.
  5. Repeat on the search or update flow if the employee ID or record version is generated server-side.

If the flow uses client-side storage to hold values, NeoLoad may not expose the value as a typical HTTP request parameter. In that case, document the limitation and do not assume the script is fully correlated unless you have evidence from the application or browser state.

6. Common correlation mistakes

  • Using the recorded literal instead of the extracted variable: the script may fail after the first run.
  • Extracting the wrong value: a token or field from the wrong response can create strange failures.
  • Not validating the extractor: a regex that matches too much can grab the wrong data and break the request.
  • Using one value across multiple users: values must remain tied to the user or session they belong to.
  • Ignoring the application contract: some values are required only after page load or state change.
