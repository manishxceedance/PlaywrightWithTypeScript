How to use package steps

  • Load order: cucumber.cjs loads package hooks and dist/steps/**/*.js; feature files can use these expressions without project-owned duplicates.
  • Scenario state: values assigned in tables or extracted from bodies are stored in scenarioVariables and referenced as {{variableName}}.
  • Authentication: headers support {{basicAuth}}, {{basicAuth:ID_VAR,SECRET_VAR}}, {{accessToken}}, and {{accessToken:TOKEN_VAR}}.
  • Paths: JSON checks accept JSONPath such as $.items[*].id; XML checks accept XPath. File paths are workspace-relative.
  • Matching: object matching is partial. Arrays default to ordered sequence matching. Set isSequence to false for order-independent matching.
  • Types and dates: accepted types are string, number, boolean, and date; integer and decimal normalize to number. Date tokens include YYYY, YY, MMM, MM, DD, HH, mm, and ss.
  • Non-empty values: use {{notEmpty}} in expected JSON or table values.
  • Lifecycle: the package closes the API request context in an After hook.

Recommended learning exercise

  1. Build one GET scenario using only client, URL, send, status, and field steps.
  2. Build one POST scenario with a file payload and store the created ID.
  3. Use that ID in path parameters for GET, PATCH, and DELETE.
  4. Add one unordered collection match, one uniqueness check, and one date-format check.
  5. Run the feature and inspect sanitized API request/response evidence in the report.
